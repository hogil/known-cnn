# 260510 — phase 26 — majority vote vs prob averaging

## Finding

Re-aggregated the same iter-39 4-bag (NEW HEADLINE
components: 24_LS030_seed42 + 26 B + 26 D + 26 H) using the
per-chip `prob_<class>` columns from `preds_chip.parquet`,
to test whether prob averaging matches the canonical
majority vote `≥ 2 / 4`.

| aggregation                              | v15 bit-F1 | ni_FAR  |
|------------------------------------------|-----------:|--------:|
| **Majority vote `≥ 2 / 4` (canonical)**  | **0.9992** | 0.00 %  |
| Prob avg + uniform threshold sweep       |     0.9741 | 3.75 %  |
| Prob avg + per-class threshold (5⁴ grid) |     0.9741 | 3.75 %  |
| Prob avg, mega 7-bag                     |     0.9905 | 1.25 %  |

Majority vote dominates by **+0.0251 v15 bit-F1**. Per-
class threshold tuning over a 5⁴ grid does not close the
gap (identical 0.9741 → not a threshold-search artefact).
A 7-bag prob average (0.9905) still loses by +0.0087.

## Interpretation

Each component's `preds_chip.parquet` decision is **already
post-thresholded** by the cell's I3 / I6 / I7 / I10
inference variant (per-class `max_prob` + invalid-score
gating). Majority vote aggregates four chip-by-chip
calibrated discrete decisions; prob averaging discards the
per-cell calibration and re-applies a single (or 4-class)
threshold after averaging — collapsing the per-chip
flexibility.

Counter-textbook: Lakshminarayanan 2017 (Deep Ensembles)
and Hinton 2015 (KD prep) both recommend soft averaging.
In our setting, ensemble members differ in **decision
rule**, not just weights — so vote-first-then-count
preserves the calibration that average-first-then-threshold
discards.
